# gudlet

Turn a Waveshare 1.69" LCD board into a tiny USB monitor.

gudlet is Rust firmware that lets your computer use the board as a second
display over a USB data cable. It speaks
[GUD, the Generic USB Display protocol](https://github.com/notro/gud/wiki).
On macOS, use it with [GUD Display](https://github.com/fcjr/gud-display-mac).
On Linux, use a kernel with the `gud` driver enabled.

## Supported boards

| Board | Status |
|---|---|
| [Waveshare ESP32-S3-Touch-LCD-1.69](https://www.waveshare.com/esp32-s3-touch-lcd-1.69.htm) | Tested on hardware with GUD Display on macOS; supports LZ4 compression |
| [Waveshare RP2040-Touch-LCD-1.69](https://www.waveshare.com/rp2040-touch-lcd-1.69.htm) | Builds successfully; not yet tested on hardware |

The display is 240×280 pixels, or 280×240 with the landscape build option.
Both boards support brightness control. Touch input and the boards' other
sensors are not implemented.

These are USB full-speed devices. Frame rate depends on how much of the
screen changes and how well the content compresses. An ESP32-S3 test with
an animated screen sustained about 30 full-panel updates per second; this
is not a guaranteed frame rate for every workload.

## Flash an ESP32-S3 board

The flashing scripts currently target macOS. You need a USB data cable,
[Rust via rustup](https://rustup.rs/), [just](https://github.com/casey/just),
and [uv](https://docs.astral.sh/uv/getting-started/installation/).

Install the ESP32 tools and load the environment generated by
[espup](https://github.com/esp-rs/espup):

```sh
cargo install espup espflash --locked
espup install --targets esp32s3
. "$HOME/export-esp.sh"

git clone https://github.com/fcjr/gudlet.git
cd gudlet
```

For the first flash, unplug the board, hold BOOT, plug it back in, then
release BOOT. Connect only the board you want to flash and run:

```sh
just flash esp32s3
```

Once gudlet is running, subsequent updates need no button presses:

```sh
just flash
```

The command detects the board, builds the firmware, enters its bootloader,
flashes it, and reboots it. If an older firmware ignores the command, hold
BOOT alone for one second and run it again. If no download port appears,
repeat the first-flash steps above.

For an RP2040 board, install `elf2uf2-rs`, hold BOOT while plugging it in,
and wait for the `RPI-RP2` drive. Then run `just flash rp2040`. See the
[RP2040 guide](firmware/rp2040/README.md) for setup details and limitations.

## Use the display

On macOS, launch [GUD Display](https://github.com/fcjr/gud-display-mac) and
grant Screen Recording permission when requested. The board appears in
System Settings > Displays, where you can arrange it beside your main
screen or enable mirroring. Use the app's menu to adjust brightness.

On Linux, the `gud` driver handles the USB display. Your desktop's display
settings control its arrangement. This firmware has been tested with the
Mac app; Linux hardware testing is still pending.

To rotate the panel at build time:

```sh
just features=landscape flash esp32s3
```

To identify the connected board or read its diagnostic counters:

```sh
just detect
just console
```

If the display stays blank, check that the cable carries data, that
`just detect` finds the board, and that the host app or Linux driver is
running. The [ESP32-S3 guide](firmware/esp32s3/README.md) covers bootloader
recovery and the serial console in more detail.

## Development

```sh
just test            # test shared protocol and panel code on the computer
just build esp32s3   # compile without flashing
just build rp2040
just check           # run shared tests and build both firmware targets
```

Both boards share the GUD protocol implementation in `crates/gud-protocol`
and the ST7789 panel driver in `crates/gud-panel`. USB handling and board
setup live under `firmware/`. The ESP32-S3 uses a patched Embassy USB driver
under `vendor/` to receive multiple packets per transfer.
